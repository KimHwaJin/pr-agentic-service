# Tool 파일 작성 규칙

tool은 `<TOOLS_ROOT>/<카테고리>/<tool 이름>.py`에 둡니다. 파일 이름과 같은 이름의 최상위 함수 하나가 tool이고, 같은 파일에 보조 함수, 클래스, 상수를 함께 둘 수 있습니다. tool 호출 하나는 노트북 셀 하나가 되고, 셀은 같은 커널에서 이어 실행됩니다.

## 셀에 들어가는 것

| 파일 최상위 요소 | 셀 | 비고 |
| --- | --- | --- |
| `import`, `from ... import` | 들어감 | `from _lib...` 줄은 헬퍼 코드로 바뀜 |
| 함수, 클래스 정의 | 들어감 | 데코레이터 포함, 파일 순서대로 |
| 변수(상수) 대입 | 들어감 | 함수 호출이 들어간 대입은 툴을 실행할 때마다 다시 계산되므로 로드 경고 |
| 모든 docstring | 빠짐 | 모듈, tool 함수, 보조 함수, 중첩 함수, 클래스, 메서드. docstring만 있던 본문은 `pass` |
| 문자열 메모, 함수 밖 주석 | 빠짐 | 함수 안 주석은 남음 |
| `if __name__ == "__main__":` 블록 | 빠짐 | 로컬 테스트 코드는 여기에 |
| 그 밖의 최상위 문장 (`print`, 함수 호출, `if`, `for` 등) | 로드 오류 | 파일과 셀의 동작이 달라지지 않도록 막음 |

tool 함수의 docstring은 셀에서는 빠지지만 에이전트에게 보여 주는 tool 설명(첫 줄, `Args:`)으로 쓰입니다. 결과 dict의 키(outputs)는 tool 함수의 `return {...}` 리터럴에서 읽으므로 tool 함수가 결과 dict를 직접 반환해야 합니다. docstring은 `def` 줄과 다른 줄에 씁니다.

## 이름 규칙

셀은 한 커널을 공유하므로 로더가 다음 경우를 로드 오류로 막습니다. 해당 tool은 "읽지 못한 tool"로 표시됩니다.

- 보조 함수나 상수 이름이 다른 tool 이름과 같음
- 다른 파일에 같은 이름이 다른 내용으로 정의됨 (`_lib`의 같은 헬퍼를 여러 tool이 쓰는 것은 괜찮음)
- `_agentic_observe`, `_r_s<N>_t<M>`처럼 생성 코드가 쓰는 이름

보조 함수와 상수 이름 앞에 `_`를 붙이는 것을 권장합니다(필수 아님). 에이전트가 직접 쓰는 코드의 변수와 겹칠 가능성이 줄고, 노트북에서 내부 함수임이 드러납니다. 같은 이유로 `import`는 가능하면 함수 안에 둡니다.

## 공용 헬퍼 (`_lib`)

여러 tool이 쓰는 함수는 `<TOOLS_ROOT>/_lib/<모듈>.py`(하위 폴더 가능: `_lib/io/excel.py` → `_lib.io.excel`)에 두고 tool 파일 최상위에서 가져옵니다.

```python
from _lib.stats import iqr_filter, zscore


def detect_outliers(data, column: str) -> dict:
    ...
```

- 셀을 만들 때 이 줄이 빠지고, 가져온 함수와 그 함수가 쓰는 헬퍼, 상수, import만 tool 코드 앞에 펼쳐 넣습니다. 쓰지 않는 함수는 들어가지 않습니다. 헬퍼 모듈끼리 `from _lib...`로 가져오는 것도 됩니다(순환은 오류).
- 별칭(`as`), `*`, `import _lib.x` 형태는 쓸 수 없습니다.
- 헬퍼 파일도 tool 파일과 같은 규칙(최상위는 정의만, docstring 제거)을 따릅니다.
- 이름이 `_`로 시작하는 경로(`_lib/` 등)는 tool로 읽지 않습니다.
- 확장 카탈로그(`CATALOG_EXTENSIONS`)의 `_lib`에 같은 이름의 모듈이 있으면 뒤의 것이 이깁니다.
- 툴 루트를 `PYTHONPATH`에 두면 로컬에서도 같은 import로 실행·테스트할 수 있습니다.

헬퍼 코드도 셀에 들어가므로 tool 버전(`tool_version`, 셀에 보내는 tool 코드의 sha256)은 헬퍼를 고치면 함께 바뀝니다.
