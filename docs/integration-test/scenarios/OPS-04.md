# OPS-04 pr-batch를 내린 채 배치 화면

| 항목 | 값 |
| --- | --- |
| 서비스구분 | OPS 장애·설정·부하 |
| 우선순위 | P1 |
| 화면 | 일부 화면 + 보조 확인 · pr-batch 중지는 운영 |
| 필요 권한 | 운영 |
| 단독 수행 | 예 |

## 1. 목적
pr-batch가 내려가도 배치 화면이 표준 오류를 보이고, 다른 화면은 정상인지 확인합니다.

## 2. 사전 조건
- 운영 담당(pr-batch 중지·기동)
- **단독 수행**

## 3. 수행 절차
처음 수행하는 사람은 아래 3-1절 "화면 조작 안내"를 먼저 읽습니다. 번호 줄은 할 일이고, 그 아래 작은 항목은 실제로 누르고 입력하고 확인할 내용입니다. "※ 미확인"은 코드로 확인하지 못해 환경에서 한 번 확인이 필요한 내용입니다. 우리 화면(`/dev/`)은 테스트를 수행하기 위한 보조 도구이고 통합 테스트 대상이 아닙니다. 통과·실패는 서버 응답(상태 코드, 응답 본문, 이벤트)과 세 서비스의 기록으로 판정하고, 화면에 보이는 글자나 버튼은 그 값을 읽는 수단으로만 씁니다.

1. 운영 담당이 pr-batch를 내립니다.
   - 단독 수행입니다. 운영 담당이 pr-batch를 내립니다(Pod 0개).
   - 운영 방법: 배포 도구에서 pr-batch를 중지합니다(인스턴스 수 0). 중지 전 인스턴스 수를 적어 둡니다. 내려간 시각을 적습니다.
2. A가 **배치** 메뉴를 엽니다.
   - A로 왼쪽 **배치**를 누릅니다.
   - 요청·응답 창(**현재 대화만** 끔)에서 `GET /api/v1/batch/batches?limit=100` 줄이 상태 502이고 응답 본문이 `code`와 `message`("pr-batch is not reachable")를 가진 형식인지 봅니다.
3. A가 채팅으로 분석을 요청합니다.
   - A로 **새 대화**에서 "nce 데이터 불러와서 기술통계 보여줘"를 보내 끝까지 진행합니다. `GET /api/v1/runs/<run id>`의 `status`가 `succeeded`인지 봅니다.
4. pr-batch를 올립니다.
   - 운영 담당이 pr-batch를 올립니다. A가 **배치**를 다시 눌러 200으로 열리는지 확인하고 끝났다고 알립니다.
   - 운영 방법: 배포 도구에서 pr-batch를 원래 인스턴스 수로 다시 올립니다. 요청을 받기 시작한 시각을 Ready 시각으로 초 단위까지 적습니다.

## 3-1. 화면 조작 안내

**접속과 로그인**
- 브라우저는 Chrome 또는 Edge를 씁니다. 주소창에 우리 화면 주소 `https://<host>/dev/`를 넣습니다. `<host>`는 환경마다 다르므로 테스트 담당이 공지한 dev 또는 prd 주소를 씁니다.
- 주소를 열면 회사 SSO 로그인 화면으로 넘어갑니다. 사번과 비밀번호로 로그인하면 우리 화면으로 돌아옵니다. "로그인하지 못했습니다"가 나오면 **다시 로그인**을 누르고, 그래도 안 되면 수행을 멈추고 운영 담당에게 알립니다.
- 지금 누구로 들어와 있는지는 화면 왼쪽 맨 아래 이름 칸에서 봅니다. 이름 아래에 사번이 있고, 칸을 누르면 "사번 … · 관리자" 또는 "사번 … · 일반 사용자"와 **로그아웃**이 나옵니다. 관리자는 이름 옆에 "관리자" 표시가 붙고 왼쪽 메뉴에 **시스템**이 보입니다.
- 이 문서의 계정 이름: **관리자**는 PREP-09에서 관리자로 로그인한 사번, **일반 A**와 **일반 B**는 테스트용 일반 사번 두 개입니다. 어느 사번이 A, B인지는 테스트 담당이 정해 둔 값을 씁니다.
- 사번을 입력하는 칸에는 항상 소문자로 넣습니다(예: `a10054`).

**화면 구성**
- 왼쪽 메뉴는 위에서부터 **새 대화**, **프로젝트**, **워크플로우**, **실행 이력**, **배치**, (관리자만) **시스템**입니다. 그 아래가 대화 목록, 맨 아래가 내 이름 칸입니다.
- 오류가 나면 화면 위쪽에 빨간 오류 메시지가 뜹니다. 메시지에는 오류 코드와 "요청 ID …"가 붙어 있고, 요청 ID를 누르면 복사됩니다. 결함을 적을 때 이 요청 ID를 함께 적습니다.

**요청·응답 창 보는 법**
- 화면 오른쪽 위 구석의 **요청·응답 N** 버튼을 누르거나 Ctrl+`(숫자 1 왼쪽 키)를 누르면 열립니다. 이 화면이 서버에 보낸 요청과 받은 응답이 최신 순으로 쌓입니다.
- 목록 한 줄은 시각, 방식(GET·POST 등), 경로, 상태 코드, 걸린 시간입니다. 줄을 누르면 오른쪽에 **요청 본문**, **응답 본문**(각각 **복사** 버튼), 접혀 있는 **헤더**가 나옵니다.
- 원하는 요청을 찾으려면 위쪽 "경로·메서드·상태로 거르기" 칸에 경로 일부(예: `users/me`)나 상태 코드(예: `403`)를 넣습니다.
- **현재 대화만**이 켜져 있으면 지금 열어 둔 대화의 요청만 보입니다. 채팅이 아닌 화면(시스템, 배치, 실행 이력)의 요청이 안 보이면 이 체크를 끕니다.
- **SSE**가 켜져 있으면 경로가 `/sessions/…/events`인 줄이 보입니다. 이 줄을 누르면 "받은 이벤트 N건"이 최신 순으로 나오고, 이벤트마다 종류(`run_status`, `hitl_request`, `execution_completed`, `artifact` 등)와 내용이 있습니다.
- **오류만**을 켜면 실패한 요청만 남고, **지우기**는 목록을 비웁니다. 확인하려는 동작 직전에 **지우기**를 누르면 찾기 쉽습니다.

**채팅 화면 쓰는 법**
- 어느 프로젝트에서 대화할지 먼저 정합니다. 왼쪽 **프로젝트**를 누르고 쓸 프로젝트 카드를 누릅니다("기본" 표시가 있는 것이 처음 로그인 때 만들어진 프로젝트).
- 왼쪽 **새 대화**를 누르면 "무엇을 분석해 볼까요?" 화면이 나옵니다. 아래 입력창("분석하고 싶은 내용을 입력하세요")에 문장을 넣고 Enter를 누르거나 오른쪽 화살표 버튼을 누르면 전송됩니다. 줄을 바꾸려면 Shift+Enter입니다.
- 입력창 아래에 왼쪽부터 이미지 첨부, **모델** 선택, **코드 레벨** 선택이 있습니다. 따로 말이 없으면 모델은 처음 값 그대로, 코드 레벨은 "코드 레벨 · 기본"으로 둡니다.
- 보낸 뒤에는 "생각하는 중", "코드 실행 중 · N단계", "확인을 기다리는 중" 같은 진행 표시가 나옵니다. 이 동안 전송 버튼은 **중지** 버튼(네모)으로 바뀝니다.
- 끝나면 답변이 나오고, 분석을 실행했다면 답변 아래에 첨부가 붙습니다. "MD"는 리포트, "IPYNB"는 노트북이고 각각 **보기** 링크로 새 탭에서 열립니다. 답변 아래의 "런 xxxxxxxx" 꼬리표가 그 답변의 run ID입니다.
- 왼쪽 대화 목록에서 대화를 누르면 다시 열립니다. 대화 줄에 마우스를 올리면 이름 바꾸기와 삭제 아이콘이 나옵니다.

**배치 화면 쓰는 법**
- 왼쪽 **배치**를 누릅니다. 위쪽 탭은 **배치**, **스크립트**, **리포트**이고, 오른쪽 위에 **스크립트 등록**과 **새 배치** 버튼이 있습니다. "불러오지 못했습니다"가 나오면 pr-batch 쪽 문제이니 운영 담당에게 알립니다.
- **스크립트 등록** 창: "이름"(비우면 파일 이름), "노트북 파일 (.ipynb)" 또는 "세션 노트북 artifact ID" 중 하나를 넣고 **등록**을 누릅니다.
- **새 배치** 창: "이름", "프로젝트", "스크립트", "버전"(비우면 최신), "런타임", "일정"을 정하고 **만들기**를 누릅니다. 일정은 **수동 실행만**, **일정 간격 (분)**, **매일 정해진 시각**, **Cron** 중에서 고르고, 고르면 값 칸과 시작·종료 시각 칸이 나옵니다. 시간대는 한국 시간입니다. 만든 뒤 **켜기**를 눌러야 일정이 동작합니다.
- **배치** 탭 목록의 칸은 이름, 프로젝트, 스크립트, 일정, 다음 실행, 상태(켜짐 / 꺼짐)입니다. 줄 오른쪽에 **지금 실행**, **켜기** 또는 **끄기**(켤 수 없으면 사유 글자), **수정**, **삭제**가 있습니다.
- 배치 줄(이름)을 누르면 그 배치의 **실행 이력** 창이 열립니다. 탭은 **실행**과 **건너뛴 일정**이고, 오른쪽 위 **↻**가 새로 고침입니다. 자동으로 바뀌지 않으므로 상태 변화를 보려면 **↻**를 여러 번 누릅니다.
- 실행 이력 표의 칸은 상태, 실행, 방식, 시작, 종료, 소요, 노트북(**보기**), 리포트, (진행 중이면) **취소**입니다. 상태 옆에 ⚠나 ⓘ가 있으면 마우스를 올려 사유를 봅니다. 줄을 누르면 executor 실행 상세 창이 열립니다.
- **리포트** 탭은 배치 실행이 성공한 뒤 자동으로 만들어지는 리포트 목록입니다. 상태는 대기, 노트북 준비 대기, Agent 작성 중, 저장 중, 완료, 실패입니다. 줄을 누르면 리포트가 열립니다.

**운영 담당과 함께 할 때**
- "운영 담당이 …"로 시작하는 단계는 수행자가 직접 하지 않습니다. 배포 권한이 있는 운영 담당에게 요청하고, 끝났다는 답을 받은 뒤 다음 단계로 갑니다. 내부망에서는 kubectl을 쓸 수 없으므로 모든 변경은 "값을 고쳐 다시 배포"로 합니다. 아래는 운영 담당이 하는 일입니다.
- **우리 서비스 설정을 잠깐 바꾸기**: 설정값은 저장소 루트의 `config.<환경>.yml`(prd는 `config.prd.yml`)에 있고 이미지에 함께 들어갑니다. 단계에 적힌 이름의 줄을 찾아 값을 고친 뒤 이미지를 다시 만들어 배포합니다. 고치기 전의 줄을 그대로 복사해 보관합니다.
- **환경 변수로 넣을 수 있는 환경이라면** 파일을 고치지 않아도 됩니다. 같은 이름의 환경 변수가 설정 파일보다 우선하므로, 배포 설정의 환경 변수에 `이름=값`을 넣어 배포하고 끝나면 그 환경 변수를 지워 다시 배포합니다. 목록 값은 JSON으로 넣습니다(예: `SSO_ALLOWED_ORIGINS=["https://sso.example.com"]`).
- **되돌리기**: 보관한 원래 줄로 되돌려 다시 배포합니다. 테스트용으로 고친 값이 저장소의 main이나 internal/gaia에 남지 않게, 테스트용 변경은 커밋을 되돌리거나 별도 브랜치에서 배포합니다.
- **배포가 끝난 시각**: 새 버전이 떠서 요청을 받기 시작한 시각입니다. 배포 도구의 완료 표시로 확인하고, 화면에서는 `https://<host>/dev/`가 다시 열리는지로 확인합니다. 시간 기준이 있는 시나리오는 이 시각을 초 단위로 적습니다.
- **재시작만**: 값을 바꾸지 않고 같은 버전을 다시 배포합니다.
- **서비스 내리기와 올리기**(executor, pr-batch): 배포 도구에서 그 서비스를 중지(인스턴스 수 0)하고, 끝나면 원래 수로 다시 올립니다. 내려갔는지는 우리 화면에서 그 서비스에 가는 요청이 502 등으로 실패하는지로 확인할 수 있습니다(executor는 **실행 이력**, pr-batch는 **배치**).
- **로그 찾기**: 사내 로그 조회 도구에서 서비스 이름과 시각 범위를 정하고 단계에 적힌 로그 이름으로 검색합니다. 로그 확인을 요청하는 사람은 검색어, 동작한 시각(초 단위), 있으면 request id나 run id를 전달합니다. 운영 담당은 찾은 줄을 그대로 복사해 주고, 수행자는 8절 증빙에 붙입니다.
- ※ 미확인: 내부망의 배포 도구(파이프라인 이름, 환경 변수를 넣는 자리, 서비스를 중지하는 메뉴)와 로그 조회 도구는 이 문서에 적지 못했습니다. executor와 pr-batch의 설정 방식은 각 담당의 방법을 따릅니다.
- "단독 수행: 예"인 시나리오는 다른 사람의 테스트를 깨뜨립니다. 시작 전에 테스트 채널에 시작을 알리고, 6절 정리까지 끝낸 뒤 끝났다고 알립니다.

**끝난 뒤 기록**
- 각 단계에서 예상 결과와 비교할 화면을 캡처합니다(Windows는 Win+Shift+S). API 키 원문, 쿠키, CSRF 토큰이 보이면 가리고 올립니다.
- 이 페이지 7절 "수행 기록"에 환경, 수행자, 수행 일시, 빌드 커밋, 결과를 적고, 8절에 단계별 실제 결과와 증빙(캡처, 응답 본문, request id, run id, 실행 ID)을 붙입니다.
- 상황판(엑셀)에서 이 시나리오의 TC 줄마다 상태를 **통과** 또는 **실패**로 바꾸고 시작일자와 완료일자를 적습니다. 4절 예상 결과의 한 줄이 TC 하나입니다.
- 판정 근거는 서버가 준 값입니다. 4절 예상 결과에 화면 표시로 적힌 항목도 요청·응답 창의 응답 본문이나 이벤트에서 같은 값을 확인해 판정합니다. 화면만 이상하고(글자 깨짐, 버튼 위치, 새로 고침해야 보임 등) 서버 응답은 예상과 같으면 **통과**이고, 화면 문제는 결함으로 올리지 않고 테스트 담당에게 따로 알립니다.
- 화면으로 수행할 수 없게 되면(화면이 열리지 않음 등) 같은 요청을 **시스템 > API 호출 시험**이나 curl로 보내 수행해도 됩니다.
