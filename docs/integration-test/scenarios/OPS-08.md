## 1. 목적
없는 모델과 LLM 장애에서 오류 원인이 보이는지 확인합니다.

## 2. 사전 조건
- 우리 tenant 키, A 사번과 프로젝트 ID
- 운영 담당(LLM 장애 흉내: 키를 틀리게 배포 등)

## 3. 수행 절차
1. 관리자로 **시스템 > API 호출 시험** 탭을 엽니다. 시나리오 **OPS-08**을 키, A 사번, 프로젝트 ID로 보냅니다.
2. 운영 담당이 `LLM_API_KEY`를 틀린 값으로 배포합니다.
3. A가 채팅으로 질문합니다.
4. 키를 되돌립니다.

## 4. 예상 결과
- 1: 422 `UNKNOWN_MODEL`
- 3: run 실패, 오류 문구에 원인(권한 등)과 게이트웨이 메시지·오류 ID. 주소·비밀값은 가려짐
