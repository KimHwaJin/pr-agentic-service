# PREP-09 관리자 최초 로그인 → /users/me에서 admin 확인 → 테스트 키 3개 발급(일반·마스터)

| 항목 | 값 |
| --- | --- |
| 서비스구분 | PREP 사전 준비 |
| 우선순위 | P0 |
| 화면 | O 우리 화면만 · 시스템 > API 키 |
| 필요 권한 | 관리자 |
| 단독 수행 | 아니오 |
| 연동 경로 | - |

## 1. 목적
관리자 첫 로그인으로 관리자 권한을 받고, 시험용 API 키를 발급합니다.

## 2. 사전 조건
- `ADMIN_EMPLOYEE_IDS`에 관리자 사번이 들어간 상태로 배포됨

## 3. 수행 절차
처음 수행하는 사람은 아래 3-1절 "화면 조작 안내"를 먼저 읽습니다. 번호 줄은 할 일이고, 그 아래 작은 항목은 실제로 누르고 입력하고 확인할 내용입니다. "※ 미확인"은 코드로 확인하지 못해 환경에서 한 번 확인이 필요한 내용입니다. 우리 화면(`/dev/`)은 테스트를 수행하기 위한 보조 도구이고 통합 테스트 대상이 아닙니다. 통과·실패는 서버 응답(상태 코드, 응답 본문, 이벤트)과 세 서비스의 기록으로 판정하고, 화면에 보이는 글자나 버튼은 그 값을 읽는 수단으로만 씁니다.

1. 관리자로 처음 로그인합니다.
   - `ADMIN_EMPLOYEE_IDS`에 넣은 사번으로 `https://<host>/dev/`에 처음 로그인합니다. 이 사번은 이전에 로그인한 적이 없어야 합니다.
2. 왼쪽 아래 이름 옆에 "관리자" 표시와 **시스템** 메뉴가 있는지 봅니다.
   - 화면 왼쪽 맨 아래 이름 옆에 "관리자" 표시가 있고, 왼쪽 메뉴 맨 아래에 **시스템**이 보이는지 봅니다.
   - 보이지 않으면 일반 사용자로 만들어진 것입니다. 운영 담당이 `uv run python scripts/set_user_role.py --env <env> <사번> admin`으로 바꾼 뒤 30초 지나 새로 고칩니다.
3. **시스템 > API 키 > 새 키 발급**에서 우리 tenant 일반키를 만듭니다(tenant `dtest-agent-service`, "이 서비스의 tenant로 발급" 체크, 종류 일반키).
   - **시스템** > **API 키** 탭 > **새 키 발급**을 누릅니다.
   - 이름 `it-own-std`, tenant `dtest-agent-service`를 넣고 "이 서비스의 tenant로 발급합니다"를 체크합니다. 종류는 "일반키"를 고르고 **발급**을 누릅니다.
   - "발급된 키"가 나오면 6번대로 복사해 둔 뒤 **닫기**를 누릅니다.
4. 같은 방법으로 우리 tenant 마스터키를 만듭니다(종류 마스터키).
   - 다시 **새 키 발급**을 누릅니다. 이름 `it-own-master`, tenant `dtest-agent-service`, 체크 상자 체크, 종류 "마스터키"로 **발급**합니다.
5. 외부 tenant 일반키를 만듭니다(tenant `it-ext`, 체크 안 함, 종류 일반키).
   - 다시 **새 키 발급**을 누릅니다. 이름 `it-ext-std`, tenant `it-ext`, 체크 상자는 체크하지 않고, 종류 "일반키"로 **발급**합니다.
6. 발급 창의 **복사** 버튼으로 키 원문을 복사해 테스트 담당만 보관합니다.
   - 키마다 발급 직후 창에서 **복사**를 누르고("복사됨"으로 바뀜) 메모장에 "키 이름 = 원문" 형태로 붙여 둡니다. 창을 닫으면 원문을 다시 볼 수 없습니다.
   - 세 키 원문은 테스트 담당 한 사람이 보관하고, 수행자가 필요할 때 사내 비밀값 전달 수단으로 건넵니다. 문서나 대화방에 붙이지 않습니다.
   - 이름은 예시입니다. 다른 이름을 썼다면 어느 키가 무엇인지 표로 적어 둡니다.

## 3-1. 화면 조작 안내

**접속과 로그인**
- 브라우저는 Chrome 또는 Edge를 씁니다. 주소창에 우리 화면 주소 `https://<host>/dev/`를 넣습니다. `<host>`는 환경마다 다르므로 테스트 담당이 공지한 dev 또는 prd 주소를 씁니다.
- 주소를 열면 회사 SSO 로그인 화면으로 넘어갑니다. 사번과 비밀번호로 로그인하면 우리 화면으로 돌아옵니다. "로그인하지 못했습니다"가 나오면 **다시 로그인**을 누르고, 그래도 안 되면 수행을 멈추고 운영 담당에게 알립니다.
- 지금 누구로 들어와 있는지는 화면 왼쪽 맨 아래 이름 칸에서 봅니다. 이름 아래에 사번이 있고, 칸을 누르면 "사번 … · 관리자" 또는 "사번 … · 일반 사용자"와 **로그아웃**이 나옵니다. 관리자는 이름 옆에 "관리자" 표시가 붙고 왼쪽 메뉴에 **시스템**이 보입니다.
- 이 문서의 계정 이름: **관리자**는 PREP-09에서 관리자로 로그인한 사번, **일반 A**와 **일반 B**는 테스트용 일반 사번 두 개입니다. 어느 사번이 A, B인지는 테스트 담당이 정해 둔 값을 씁니다.
- 사번을 입력하는 칸에는 항상 소문자로 넣습니다(예: `a10054`).

**화면 구성**
- 왼쪽 메뉴는 위에서부터 **새 대화**, **프로젝트**, **워크플로우**, **실행 이력**, **배치**, (관리자만) **시스템**입니다. 그 아래가 대화 목록, 맨 아래가 내 이름 칸입니다.
- 오류가 나면 화면 위쪽에 빨간 오류 메시지가 뜹니다. 메시지에는 오류 코드와 "요청 ID …"가 붙어 있고, 요청 ID를 누르면 복사됩니다. 결함을 적을 때 이 요청 ID를 함께 적습니다.

**시스템 > API 키 쓰는 법**
- 관리자로 왼쪽 **시스템** > 위쪽 탭 **API 키**를 누릅니다. 표의 칸은 이름, tenant, 종류(일반 / 마스터), 키(앞부분만), 상태(사용 중 / 폐기), 마지막 사용, 발급입니다.
- **새 키 발급**을 누르면 창이 열립니다. "이름", "tenant", "이 서비스의 tenant로 발급합니다" 체크 상자, "종류"(일반키 / 마스터키), "설명 (선택)"을 채우고 **발급**을 누릅니다.
- 발급되면 같은 창에 "발급된 키"가 한 번만 보입니다. **복사**를 눌러 메모장 등 안전한 곳에 붙여 둡니다. 창을 닫으면 다시 볼 수 없습니다.
- 줄 오른쪽 버튼: **재발급**(같은 이름으로 새 키, 지금 키는 바로 끊김), **폐기**(그 키 하나), **tenant 전체 폐기**(그 tenant의 모든 키). 모두 확인 창이 한 번 뜨고 **확인**을 눌러야 실행됩니다. 되돌릴 수 없으니 줄의 이름과 tenant를 다시 확인하고 누릅니다.
- 폐기한 키는 상태가 "폐기"로 바뀌고 버튼이 사라집니다.

**끝난 뒤 기록**
- 각 단계에서 예상 결과와 비교할 화면을 캡처합니다(Windows는 Win+Shift+S). API 키 원문, 쿠키, CSRF 토큰이 보이면 가리고 올립니다.
- 이 페이지 7절 "수행 기록"에 환경, 수행자, 수행 일시, 빌드 커밋, 결과를 적고, 8절에 단계별 실제 결과와 증빙(캡처, 응답 본문, request id, run id, 실행 ID)을 붙입니다.
- 상황판(엑셀)에서 이 시나리오의 TC 줄마다 상태를 **통과** 또는 **실패**로 바꾸고 시작일자와 완료일자를 적습니다. 4절 예상 결과의 한 줄이 TC 하나입니다.
- 판정 근거는 서버가 준 값입니다. 4절 예상 결과에 화면 표시로 적힌 항목도 요청·응답 창의 응답 본문이나 이벤트에서 같은 값을 확인해 판정합니다. 화면만 이상하고(글자 깨짐, 버튼 위치, 새로 고침해야 보임 등) 서버 응답은 예상과 같으면 **통과**이고, 화면 문제는 결함으로 올리지 않고 테스트 담당에게 따로 알립니다.
- 화면으로 수행할 수 없게 되면(화면이 열리지 않음 등) 같은 요청을 **시스템 > API 호출 시험**이나 curl로 보내 수행해도 됩니다.
- 예상과 다르면 더 진행하지 말고 상태를 **실패**로 두고 9절에 결함(재현 단계, 예상, 실제, 발생 시각, request id)을 적은 뒤 결함번호를 상황판에 넣습니다.
