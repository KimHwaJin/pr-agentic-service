# ADM-07 API 키 재발급

| 항목 | 값 |
| --- | --- |
| 서비스구분 | ADM 관리자 |
| 우선순위 | P1 |
| 화면 | O 우리 화면만 |
| 필요 권한 | 관리자 |
| 단독 수행 | 아니오 |
| 연동 경로 | I1 I2 |
| 11/01판 ID | - |

## 1. 목적
키를 재발급하면 이름·tenant·종류는 그대로 새 키가 한 번만 보이고, 이전 키는 유예 없이 끊기며, 폐기한 키는 재발급되지 않는지 확인합니다.

## 2. 사전 조건
- 관리자 로그인
- 일반 A 사번
- 운영 담당(로그 확인)

## 3. 수행 절차
1. 시스템 > API 키 > 새 키 발급에서 이름 it-adm07, tenant it-adm, 종류 마스터키로 발급하고 원문을 복사합니다(키 1).
2. API 호출 시험에서 키 1, A 사번으로 AUTH-04를 보냅니다.
3. 키 목록에서 it-adm07의 재발급을 누르고 확인합니다. 새 원문을 복사합니다(키 2). 시각을 초 단위로 적습니다.
4. 창을 닫고 목록의 it-adm07 줄을 봅니다.
5. API 호출 시험에서 키 1로 AUTH-04를 10초 간격으로 보냅니다. 키 2로도 보냅니다.
6. it-adm07을 폐기합니다. 폐기한 줄을 보고, API 호출 시험에서 X-Api-Key 보내기를 끄고 쿠키·CSRF를 켠 채 POST /api/v1/admin/api-clients/<it-adm07 id>/reissue를 보냅니다(id는 요청·응답 창의 GET /admin/api-clients 응답).
7. 운영 담당이 로그에서 api_client_reissued를 찾습니다.

## 4. 예상 결과
- 3: 제목 "API 키 재발급 · it-adm07", 복사 버튼(누르면 "복사됨"), "이 창을 닫으면 다시 볼 수 없습니다" 문구
- 4: 이름·tenant·종류(마스터) 그대로, 키 앞부분이 바뀜, 마지막 사용 "-"
- 5: 키 1은 60초 안에 401 INVALID_API_KEY(같은 서버면 바로), 키 2는 200
- 6: 폐기한 줄에 재발급 버튼 없음. API는 409
- 7: api_client_reissued client=it-adm07 tenant=it-adm by=<관리자 사번>

## 5. 확인 방법
화면, API 호출 시험 결과, 로그

## 6. 정리 (원상복구)
6에서 폐기됨

참고: 재발급(POST /admin/api-clients/{id}/reissue)
