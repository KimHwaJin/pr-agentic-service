# RUN-17 일회성 지시와 지속 선호, 분석 대상 이름을 섞어 대화

## 1. 목적
프로젝트 메모리에 오래 쓸 선호와 사용자가 이름을 댄 분석 대상(관심 대상)은 남고, 이번 한 번만의 지시는 남지 않는지, 메모리 처리마다 로그가 남는지 확인합니다.

## 2. 사전 조건
- 일반 A 로그인, 새 프로젝트(메모리 비어 있음)
- 운영 담당(로그 확인)

## 3. 수행 절차
1. 새 프로젝트에서 대화를 열고 "앞으로 그래프는 항상 한국어 제목으로 그려줘"를 보냅니다.
2. 같은 대화에서 "이번에만 상위 5개만 보여줘"를 보냅니다.
3. 답변이 끝나고 1~2분 뒤 **프로젝트 > (그 프로젝트) > 공유 메모리** 탭을 엽니다.
4. 같은 프로젝트에서 새 대화를 열고 "nce 데이터에서 SN OPEN 측정값을 LOT별로 보여줘"를 보냅니다. 계획을 승인하고 끝까지 진행합니다.
5. 1~2분 뒤 공유 메모리 탭을 다시 엽니다.
6. 같은 대화에서 "고마워"를 보냅니다.
7. 운영 담당이 로그에서 이 프로젝트 ID의 `memory_extract_done`, `memory_extract_skipped`를 찾습니다.

## 4. 예상 결과
- 한국어 제목 선호는 메모리에 있음
- "이번에만 상위 5개"는 없음
- 5: Core Interests에 "관심: … SN OPEN …" 같은 한 줄이 생김("앞으로" 같은 말이 없어도). 관심 줄이 이미 있으면 그 줄에 합쳐지고 줄 수가 늘지 않음
- 7: 4의 처리는 `memory_extract_done project=<ID> messages=… ops=… parse_failed=false parse_status=ok saved_topics=1` 이상
- 7: 6의 처리는 `memory_extract_skipped project=<ID> … reason=trivial`, 메모리 변화 없음

## 5. 확인 방법
공유 메모리 탭, 로그

## 6. 정리 (원상복구)
프로젝트 삭제 또는 메모리 정리
